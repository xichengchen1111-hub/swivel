# Real-ESRGAN 接入与安全复核

日期：2026-10-23。分支：`codex/media-batch2`。

主人在此前的效果对比中选择第 5 列 Real-ESRGAN，并明确批准为这个功能引入必要的模型和依赖，要求纯本地处理、接入后 agent 安全审查和全量测试，不安装、不推送。本次是原六项功能之后的独立改进，保留原有六个功能提交和扩展审查提交。

## 接入结果

图片和视频的 Upscale 已使用官方 **Real-ESRGAN x4plus** 权重。采用 Swift 与系统 Core ML 运行，不在 App 内附带 ncnn 可执行文件、Python、PyTorch、第三方动态库或下载器。模型随 App 附带；运行时没有模型下载、账号、上传图片或远程推理入口。最低编译目标仍为 macOS 15，没有新增隐私权限或放宽签名权限。

图片提供 2×、4×，视频提供 2×。2× 使用同一 x4plus 模型重建后逐块缩小。输出仍在源文件旁边，通过原有独占发布接口保存，不覆盖源文件或同名文件。视频保留音轨和时长；编辑器仍不开放给 MCP。

模型每次处理 256×256 的输入块，其中有效区域 128×128，四周保留 64 像素真实邻域，再裁去上下文并拼接。较小的 16/32 像素邻域在独立探针中出现较大接缝误差，因此没有采用。透明度独立插值，再恢复一次，避免半透明边缘重复乘 alpha。模型处理的是 8-bit sRGB，不能理解为无损或 HDR 保真恢复。

输入上限为 16MP；静态图解码还限制单边 8192 像素。输出上限 64MP、单边 16384 像素，因此 4× 实际最多接受 4MP 输入。模型加载和完整帧推理共用可取消的串行队列，避免多个编辑器同时预测。一次原生预测或编译只能在调用前后检查取消，不能承诺立即中断系统调用。

## 模型来源和依赖范围

模型与开发工具位于 `ThirdParty/RealESRGAN/`，完整说明在其中的 `UPSTREAM.md`。许可证与来源固定如下：

| 项目 | 固定来源及用途 | 许可 |
| --- | --- | --- |
| Real-ESRGAN | 官方 x4plus v0.1.0 checkpoint；项目许可版本 `a4abfb2979a7bbff3f69f58f58ae324608821e27` | BSD-3-Clause |
| BasicSR | `8d56e3a045f9fb3e1d8872f92ee4a4f07f886b0a` 的 RRDB 架构子集，仅供开发转换 | Apache-2.0 |
| Python 转换工具 | 独立 `build/` 环境；20 个 wheel 逐项固定版本和 SHA256 | 不进入 App 或 SwiftPM 运行时依赖 |

官方 checkpoint 的 SHA256 为 `4fa0d38905f75ac06eb49a7951b426670021be3018265fd191d2125df9d682f1`。转换前必须匹配此值，随后仅使用 `torch.load(weights_only=True)` 并严格验证参数键、形状及有限值。运行时只接受编译内三个固定文件及 SHA256，总大小 67,441,119 字节。资源通过 fd 读取、拒绝链接和额外文件，并把被校验的相同字节复制到 0700/0600 私有目录后才交给 Core ML。没有加载用户指定模型或路径的入口。

Core ML 与相同权重、相同 padding 的 PyTorch 三个小型探针最大差异为 0.518/255；两张照片的 halo64 接缝最大差异分别为 1.225/255、0.861/255。这是有限样本的转换与拼接检查，不保证任意图片没有接缝。当前 Core ML 与此前获选 ncnn 效果使用同一权重，但边界处理、后端计算和舍入会有细小差异，不声称逐像素一致，也不声称 PSNR 必定高于普通插值。

## 独立 agent 安全复核

接入后由三位 agent 分别审查模型信任边界、供应链与打包、媒体输入与保存取消；没有让实现者代替这三次独立审查。另有先前十二个任务覆盖六项功能与跨功能安全面，见 `第二批媒体功能：扩展审查与修复.md`。

| 检查面 | 发现、修复与证据 |
| --- | --- |
| 模型文件信任边界 | 发现 P3：从包 URL 重建父目录时末尾 `/` 改变 URL 身份，实际目录删除后仍留下临时清理注册。改为保存创建时的精确目录 URL；独立探针 19 项通过，确认文件和登记均清理。还覆盖哈希替换、额外空目录、软/硬链接、FIFO、超限稀疏文件和路径逃逸拒绝。 |
| 供应链与资源包 | 发现 P2：原生 macOS SwiftPM bundle 使用 `Contents/Resources` 布局，初版定位只支持扁平路径。改用 Bundle 的资源查找，补充真实布局测试及移除资源后禁止开发路径回退的检查；同时处理 Bundle 的过期 URL 缓存。核对 3 个模型文件、20 个 wheel 哈希、固定系统算子、许可和开发依赖隔离。 |
| 视频取消 | agent 建议补“第一帧开始后取消”的确定性测试。测试复现了系统 async export 内部先等待帧完成，外层停止处理通知不能先执行的问题。改为独立 exporter Task：先停止模型任务，再取消 exporter，并始终等待 exporter 结束后才清理临时输出。相同门闩测试通过，agent 重新检查各阶段竞争后未发现孤儿写入或新死锁。 |
| 媒体尺寸、输出与推理队列 | 独立检查 321602 组小尺寸 tile 几何，未见裁剪越界、重复覆盖或空洞。输入及输出尺寸在整数乘法与分配前限制；推理租约只由持有者释放，取消等待者不释放他人租约；保存继续使用独占接口。 |

原始审查、探针和日志放在忽略的 `build/review-realesrgan-*`。这些有限检查没有证明系统 Core ML、GPU 驱动、所有原生解码器或整个上游供应链无漏洞。

- 视频集成：真实短视频 2× 导出，尺寸、音轨、时长、源字节和名称通过。与独立处理的实际 CI 解码输入比较，最终视频 RMSE 为 2.2156，低于原有上限 8。初版测试把无色彩标记的 AVAssetImageGenerator 图作为参考而失败；定位色彩差异后改用实际 composition 输入，未放宽容差。
- 全量连续两次：`build/realesrgan-full-suite-1.log`、`build/realesrgan-full-suite-2.log`，均为 344 项、29 个 suite；341 项通过、3 项既有 opt-in 跳过（Doctor live 检查及 rope/card 渲染）。新模型和全部新媒体集成测试实际运行。

## 尚未验证与实际限制

- 没有安装、推送、合并或启动已安装 App；真实窗口、Finder 拖放及主人肉眼验收仍未进行。
- 没有 macOS 15 或 Intel 实机结果；部署目标及模型静态规格支持不等于实机验证。
- 没有对最长视频、最高像素输入进行峰值内存或填盘实验。64MP 输出的一份 RGBA 缓冲本身约 256MB，此外还有模型、输入、编码和系统缓存；不能把固定 tile 大小当作总内存承诺。
- 这是空间照片模型，逐帧视频可能产生纹理闪烁；没有验证长片、HDR、VFR、多音轨与所有编解码组合。短视频通过不代表长视频速度合格。
- 重建的纹理可能与真实细节不同，文字、人脸及细小图案需要视觉核对。此实现没有加入人脸修复模型或额外锐化。
- 独占发布完成后是保存提交点，极晚到达的取消不能保证撤销已完成输出。
