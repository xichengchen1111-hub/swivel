# Swivel — notes for coding agents

Swivel is a native macOS menu-bar app (Swift, AppKit, no third-party dependencies) that bundles eleven tools, each switched on or off on its own:

- **Wheel** — start dragging a file in Finder, tap a modifier key, and a menu pops up under the pointer. Drop the file on an option to convert it, open an editor (crop, compress, adjust, background, redact, metadata, annotate, collage, trim), or act on it (AirDrop, copy, move, copy path, Terminal, shelf, hang on the clothesline). Five menu templates: Wheel, List, Bookshelf, Sticky Notes, Clothesline.
- **Clothesline** — a rope under the menu bar. New screenshots first wait as a card in the bottom-right corner (like the system thumbnail); drag the card up or click it to hang it. Moving the pointer to the screen’s top edge immediately lowers the rope. Prints can be clicked (copy), double-clicked (open), held (Quick Look) or dragged away. The rope and prints are animated with a small physics model.
- **Text Capture** — local Vision OCR from a selected image, with editable text and explicit copy.
- **File Shelf** — a session-only list of file references with multiple selection and dragging out together.
- **Image Presets** — saved image size, format, quality and metadata recipes; outputs beside originals.
- **Quick Actions** — searchable keyboard panel for enabled tools and explicitly supplied files. Optional **assistant**: with the user's own API key (Claude or any OpenAI-compatible service, incl. local Ollama) a model picks one offered action for a typed request; the user runs it with Return.
- **Keep Awake** — power assertion for 30 min – 5 h or until turned off, from the ◎ menu, its page or Quick Actions.
- **Mac Doctor** — read-only diagnosis of storage/“System Data”, caches, folder sizes, slowness, apps that won’t open (“damaged”, unidentified developer), external drives, network/proxy, background items, battery and sleep. Fixes only after confirmation: caches or a leftover launch agent to the Trash (with undo), Eject, or the exact System Settings pane. Optional assistant explanation from a fully previewed, redacted report.

Optional tools are opt-in and default off. Each can be used independently of Wheel.

The owner is a Chinese-speaking user; talk to them in Chinese. The app UI is English with translations (see Localization).

## Build, install, run

```bash
./build.sh                                   # swift build -c release → build/Swivel.app (ad-hoc signed)
./test.sh                                   # Swift Testing checks (tools, springs, hit-testing, sounds)
```

Quit the installed app normally before replacing it, so screenshot takeover can restore the user's settings. Keep a backup of the previous application when installing a development build.

Requires macOS 15+ and the Command Line Tools (Swift 6 toolchain, Swift 5 language mode). Liquid Glass uses macOS 26 APIs behind `#available`.

## Testing without a real drag

- Developer modes below work only in unbundled builds (`.build/debug/Swivel`) and validation bundles with another bundle ID; the installed `local.swivel.app` ignores all command-line modes (security fix in 1.5.0) except exactly `Swivel --mcp`.
- `Swivel --mcp` — the MCP server for agents (stdio JSON-RPC, see README). Manual session: `printf '%s\n' '<initialize>' '<tools/list>' | .build/debug/Swivel --mcp`; for plan → apply use a FIFO so you can read the plan_id first. `SWIVEL_MCP_HISTORY_DIR=<dir>` keeps a development build's undo log out of the real one (`~/Library/Application Support/Swivel/Agent History`); the installed app ignores it. `./mcpb/pack.sh` builds `build/Swivel.mcpb`.
- `Swivel --run <convert|tools|actions|apps|codes> "<item title>" <file>...` — runs one menu item headlessly and prints `OK`/`FAIL`. A wrong title lists the available ones.
- `Swivel --demo <convert|tools|actions|apps|codes> <file> [script] [style]` — shows a menu at the pointer (for screenshots and recordings). The script is one hover index (`2`) or steps run every 0.35 s: `0,1,2,n,1,p1` (`n` next page, `pN` drop on item N without running it). The style applies to this run only.
- `Swivel --frames <wheel|list|shelf|notes|clothesline> <out dir> [light|dark]` — renders the menu's animations offscreen, 60 frames a second, to PNGs: open, a slow arc, a fast flick, back to the hub (cancel), a page turn and a drop. Prints mean and slowest draw time; `SWIVEL_FRAMES_SCALE=2` renders at Retina size, `SWIVEL_FRAMES_LOG=1` lists slow frames.
- `Swivel --feedback <check|play>` — `check` reports whether the trackpad actuator and the sounds are ready; `play` runs every haptic and sound once. To confirm haptic requests without feeling them: `/usr/bin/log stream --level debug --predicate 'eventMessage CONTAINS "AppKitActuateWithID"'` (the drop press goes through the actuator directly and doesn't appear there).
- `Swivel --edit <crop|compress|edit|bg|redact|metadata|annotate|collage|trim> <file>...` — opens one editor directly.
- `Swivel --recognize <image>` — prints OCR text without touching clipboard or screenshot settings.
- `Swivel --tool <text|shelf|quick|presets|rename|pdf|qr|library|apps|customize|shortcuts|mywheel|launcher|doctor|doctorsettings> [file]...` — isolated UI preview; skips the app delegate and background watchers, but registers the Quick Actions shortcut. Enables the optional tools in the executable's defaults domain, so use an unbundled binary or a separate validation bundle. `SWIVEL_PREVIEW_APPEARANCE=light|dark` changes only the preview's appearance.
- `SWIVEL_TAB=<0-17>` opens a settings page (general, shortcuts, style, customize, clothesline, overview, textCapture, shelf, imagePresets, quickActions, feel, colors, batchRename, pdfPages, qrCodes, appRouting, keepAwake, doctor); `SWIVEL_SHOW_ROPE=1` lowers the rope at launch.
- `Swivel --tool doctor [some.app]` opens Mac Doctor (optionally App Check on that app). `SWIVEL_DOCTOR_RENDERS=<dir> ./test.sh --filter DoctorTests` renders its settings page and the Overview in four languages, the window's Summary/Caches in four languages and every section in zh-Hans, light and dark. `SWIVEL_DOCTOR_LIVE=1 ./test.sh --filter DoctorLiveTests` runs every read-only check on this Mac and prints what it found.
- Note: `.build/release/Swivel` run directly has no bundle ID, so it reads a different defaults domain than the installed app (`local.swivel.app`).
- A process launched from the terminal can't take focus while the user is in another app; capture its window with `screencapture -l <windowID>`.

## Rules of the house

- **Security rules (2026-10 review).** Outputs claim their name with the write itself: `Paths.create` (data, O_EXCL), `Paths.publish` (a finished temporary, `renamex_np` RENAME_EXCL, placeholder fallback on exFAT) or `Paths.produce` (a tool/export/printer writes a hidden temporary beside the target, then it is published). Each starts from `Paths.preferred` and moves on to `name 2.ext`… on "file exists", so two conversions at once never replace each other or anything planted (dangling symlinks too); never pick a name with `Paths.output`/`Paths.unique` and then write to it. Moves claim theirs the same way: `Paths.move(_:into:)` (Move to…, the rope, the screenshot card's save) and `Paths.copy(_:into:)` (files hung from elsewhere) rename exclusively on one volume; across volumes (EXDEV) they copy into a hidden temporary in the destination, publish it, and only then remove the original (a file whose original can't be removed loses its copy again, so nothing has moved). Batch Rename renames through `Paths.renameExclusively`, so it also works on exFAT.  `--mcp` is the only argument the installed app accepts: stdio only (no port, no network), refused when launchd is the parent (`open`, where Swivel rather than the host would be TCC-responsible), inputs through `MCPPaths` (absolute, plain, existing regular file or folder, not a symlink itself), writes only via a `plan_*` then `apply_plan` (single use, one hour, refused if an input's lstat identity/size/mtime changed, applies serialized), every apply logged for `undo` (Trash for created files, identity-checked renames/moves back). Tool descriptions and errors are for models and stay English; UI strings go through `L()`. `MCPTests` covers these.Subprocesses go through `Shell.run` (empty stdin, stderr drained, optional watchdog, cancellable) and pass `--` before file operands. Open media with `Video.openAsset`/`Video.safeAsset` (no reference movies). Extraction keeps the archive's quarantine flag (fail closed), uses `--no-mac-metadata`, and stops near a full disk. Draft links escape invisible characters. Network access is limited to the opt-in assistant and three Mac Doctor actions the user starts with a button that says so: Test Speed (`networkQuality`), App Check (Gatekeeper may ask Apple about notarization) and Ask the Assistant (only with its own switch on and after a full preview). The assistant uses a user-supplied key in the keychain, stored per provider *and host* (a changed address finds no key), HTTPS (http only for localhost), no redirects, and it never sends file names, paths or contents (saved QR codes, named after images, are excluded from the offered actions). Document imports always pass an explicit `.documentType` (never let AppKit sniff: a renamed web archive would load remote/local resources). Extraction checks free space with `statfs`, makes staging folders accessible, flags read-only items too, and quitting stops tools and removes staging/temp files (`TemporaryItems`). Keep the hardened runtime in `build.sh` and add no entitlements that weaken it. `Tests/SwivelTests/SecurityTests.swift` covers these.
- **No third-party dependencies**, with one scoped exception the owner approved on 2026-10-22: **Mac Doctor** may embed vendored source or data from MIT, BSD or Apache-2.0 projects. Each lives in its own folder `ThirdParty/<Project>/`, built as a separate SwiftPM target used only by the Doctor feature. The folder holds the upstream `LICENSE` (plus `NOTICE` for Apache-2.0) and an `UPSTREAM.md` naming the repository, the pinned commit, what was taken and what was changed; README lists it under Acknowledgements and `build.sh` ships the licence in the app. Never vendor GPL/AGPL/LGPL, Commons Clause, FSL or unlicensed code, and no remote SwiftPM packages. A GPL tool may only be used if the user installed it, run by absolute path with fixed arguments, never bundled. Everything else uses system frameworks and the CLI tools that ship with macOS (`afconvert`, `ditto`, `tar`, `zip`). Today: `ThirdParty/ClearDisk` (MIT, cache paths and texts, data only).
- **Mac Doctor rules.** Checks only read and start from a button, never from page load or `Pane.refresh`. Commands come only from the closed `DoctorCommand` enum (fixed absolute tool and argv; spliced values pass `isPlain`/`isSafeLabel`/`isDiskIdentifier`/`validatedApp`/`validatedVolume`, picked paths after `--`); `eject` is the only one that changes anything. Admin commands are compile-time `DoctorAdminCommand` text, shown collapsed and copyable, never run, and never built from labels, paths, names or model output. Consult `DoctorPrivacy.isProtected` before reading any path (Desktop/Documents/Downloads, other apps' containers, Mail, Safari, `/Volumes`…), so no TCC prompt appears; folder scans skip protected subtrees, stay on one volume and never download cloud placeholders. Trash moves go through `DoctorTrash` only (catalogue caches and ~/Library/LaunchAgents leftovers; every folder from home down re-checked by dev/inode right before moving; `RENAME_EXCL | RENAME_NOFOLLOW_ANY`). App Check never suggests Open Anyway for revoked/blocked or unsigned apps and never offers removing quarantine or disabling Gatekeeper. Text from the Mac is shown through `DoctorText.visible`.
- **Outputs go next to the original file.** Never create a new folder for results (multi-page outputs are `name 1.png`, `name 2.png`…). Never overwrite: use `Paths.create` / `Paths.publish` / `Paths.produce`.
- **Text:** wrap every user-facing string in `L("English")` and add the 简体中文 / 繁體中文 / 日本語 translations to `Strings.table`. Menu item titles stay English internally — they are the IDs saved in Customize — and are translated only when drawn. Saved preset action IDs are `preset.<stable id>`; resolve their display titles through `Catalog.displayTitle` / `WheelItem.displayTitle`, so renaming does not lose menu customization.
- **Settings** live in `Prefs` (UserDefaults, posts `Prefs.changed`). Feature on/off goes through `Feature.isOn`.
- **Screenshot takeover** changes `com.apple.screencapture` (`location`, `show-thumbnail`). Always keep `ScreenshotTakeover.restore()` working: it runs when the feature is turned off and on quit.
- **Motion:** the clothesline's oscillators live in `RopeTuning` (pure, tested) and `RopeView.advance` runs on a `FrameDriver` with a fixed 1/240 s step. The owner asked for *gentle* motion — keep swings small and well damped; `ClotheslineFeelTests` enforces damping ratio ≥ 0.6, ≤ 2 visible swings and settling within 1.5 s. `SWIVEL_ROPE_FRAMES=<dir> ./test.sh` renders rope and card filmstrips for review.
- **Feel (手感):** anything that moves is a `Spring` driven by a `FrameDriver`, never a fixed tween or a `Timer`; retarget springs instead of restarting them. Colour and opacity are critically damped; only geometry may overshoot a little (damping ≥ 0.6), and the wheel's numbers live in `WheelView`'s `Tune`. Feedback starts on the next frame, presses respond on mouse-down, and the real work never waits for an animation. Fire haptics and sounds only through `Feedback` (one owner per moment, same frame as the visual): detents for snapping or a new item, a press for a commit, nothing on hover-off. Every motion path checks `Motion.reduced`. Research and sources: emilkowalski/skills `apple-design` (MIT), Apple's HIG on haptics, Kando/Fly-Pie (MIT) for pie-menu numbers.
- **Shelf and Quick Actions** are non-activating `ToolPanel`s: they take typing without bringing Swivel to the front (and route ⌘C/V/X/A/Z/W themselves while another app owns the menu bar). Editors open at `.floating` and drop to `.normal` once key, so they still appear when activation is refused during a Finder drop.
- **Private haptics:** `TrackpadActuator` is the only private API. It is resolved with dlopen/dlsym (never linked), skipped when System Settings turns trackpad haptics off, and can be disabled with `defaults write local.swivel.app privateHaptics -bool NO`.
- **Licensing:** Tendedero (github.com/alejandrobujan/tendedero) inspired the clothesline; its code is MIT but its name and icon are not licensed — don't use them. Don't copy code from GPL projects into this MIT-style codebase. When borrowing an idea, reimplement it.
- Don't edit sibling projects (`../atelier-focus`, `../clipline`); other sessions own them.
- Commit messages end with a `Co-Authored-By` line for the agent that wrote the change. Push to `origin main` (private repo `xichengchen1111-hub/swivel`) when the owner asks.
