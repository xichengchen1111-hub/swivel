# Swivel for Windows — 0.83 preview

Windows 独立原生实现，使用 C# / .NET 10 / WPF / Win32。**这是多批功能扩展预览，尚未与 Mac 功能齐全对等，也未完成 Windows 实机验收。** 剩余进度见 [52项功能进度表](PROGRESS.md)，逐批记录见 [PORTING.md](PORTING.md)，差异见 [兼容调研](../reports/Windows与macOS兼容调研.md)，验收步骤见 [TESTING.md](TESTING.md)。Mac 源码、构建、设置和安装保持独立。

## 0.83 新增：复制到文件夹

启用 Move Files 后，页面上有 **Choose Files to Copy…**，也可把 **Copy to Folder…** 放进 Wheel／My Wheel。选 1–100 个文件和一个本地 NTFS 目标文件夹，确认完整列表后复制；原文件不动。副本使用原名，已被占用时依次改用 `名称 2`、`名称 3`…，绝不覆盖。

使用 Windows 自带的 CopyFile2：保留所有数据流（含下载警告 Web 标记）、属性和修改时间；创建时间为新，权限沿用目标文件夹。CopyFile2 创建副本时就记下其文件身份，复制后只核对这个对象，数据流名称和大小必须与原文件一致（不逐字节比较），不一致就通过该句柄删除；若名称已被其他应用移走或替换，Swivel 不碰它并提示。无法核对时副本仍列出并提醒检查。失败或取消立即停止，已完成的副本保留。

B06 仍为部分实现：跨卷移动、文件夹树复制／移动及会话撤销副本仍待做。固定52项仍22／24／4／2，普通剩余28。原生复制测试只交叉编译，真实 Windows 未执行。新动作存入 My Wheel 后旧版可能拒绝整份设置，降级前保留升级前备份。

## 0.130 新增：保留内容的 PDF 页面工具、移动文件夹及撤销

本版合并第五轮中先完成的两个并行分支（各自通过 Windows CI 与独立审查）；视频裁切/旋转/变速分支仍在进行。

- **PDF 页面（保留内容）**：新动作 **PDF Pages…** 可选页、调整顺序（可重复）、每页加 90° 旋转，也可合并多个 PDF；新文件保存在第一个 PDF 旁边。每页自己的文字、矢量、图片和字体原样复制（自写 PDF 结构读取：传统 xref、xref 流、对象流、增量更新、继承的页面属性）。书签、表单、文档级脚本、附件以及指向页面或运行代码的注释会去掉，链接只保留 http/https/mailto。加密或损坏需修复的 PDF 拒绝。原来的栅格化 PDF 工具保留。
- **移动文件夹到…**：同一 NTFS 磁盘上把整个文件夹一次改名移入目标（不覆盖，重名时用下一个编号），目标在文件夹自身内或是它当前所在文件夹时拒绝；跨磁盘时建议改用“复制文件夹到…”。本次会话中可撤销：仍是同一个文件夹且原名称空闲才移回。
- **撤销复制文件夹**：复制结果窗口新增“将副本移到回收站…”，只有新文件夹仍是 Swivel 创建的那个且里面每一项都没变时才执行。

## 0.129 新增：照片中扫二维码、TIFF 去元数据、M4A 音频

本版合并第四轮三个并行分支（各自通过 Windows CI 与独立审查）。

- **从照片和截图读取二维码**：“读取二维码图片”和 Agent 的 read_codes 在原有严格平面读取失败后，改用自写的照片读取：灰度与局部阈值、寻像图形、任意角度旋转、轻微透视（有校正图形时）、网格采样后用纠错解码。这样读出的结果会标明“经纠错读取”；较大的码需要更正对着拍。损坏的平面码以前会拒绝，现在可能经纠错读出。没有用真实相机照片验收。
- **TIFF 去元数据**：与 JPEG/PNG 同一动作，不重新编码：每一页都保留，条带/图块字节原样复制，删除描述、EXIF、GPS、XMP、IPTC、Photoshop 与私有标签，保留 ICC 和显示所需标签，可选保留方向。BigTIFF、循环或重叠的 IFD、未知结构标签拒绝。
- **M4A 音频**：“用 Windows 解码音频”、“降低音频噪声”和“语音转文字”接受只含音频的 M4A（AAC-LC 或 ALAC），先经自写的 MP4 盒结构检查：一条音轨、无视频、无 DRM、无分片，HE-AAC 拒绝。前后静音填充可能变化；听感未验证。

## 0.128 新增：启动项启用状态、静态 WebP、Word 97–2003 .doc 正文

本版合并第三轮三个并行分支（各自通过 Windows CI 与独立审查）。

- **Doctor 启动应用（Startup Apps）**：新的只读视图把 Run 注册表项和（明确选择后）启动文件夹条目与 StartupApproved 记录按名称核对，显示“已启用 / 已禁用 / 未知”及禁用时间。只解释公开观察到的 12 字节格式（02/06 启用，03/07 禁用）；其他格式、冲突值或数据不完整都显示为未知并说明原因。RunOnce 不在范围内；没有对应启动项的 StartupApproved 值也列出。不显示命令、不做任何更改。尚未与真实 Windows 任务管理器的“启动应用”页逐项对照。
- **读取静态 WebP 图片**：按 RFC 9649 / RFC 6386 自写解码器，支持有损（VP8）、无损（VP8L 全部变换）与透明（ALPH），不依赖系统安装的 WebP 编解码器。所有图片工具、轮盘、相似照片、Agent 都能用 .webp 作为输入。动画 WebP 拒绝；ICC/EXIF/XMP 不应用。
- **读取 Word 97–2003 .doc 正文**：“检查文档文字”、五种纯文本导出、文件预览和 Agent 的 extract_text 都接受 .doc。自写复合文档与片段表读取：正文、表格（单元格为 Tab、行换行）、域结果；直接隐藏与修订删除的文字跳过。加密、Word 6/95 及更早格式拒绝；实为 RTF 或 DOCX 的 .doc 改用对应读取器。不读取宏、OLE 对象和图片。

## 0.127 新增：7z 解压、Store/MSIX 应用列表、去元数据时保留方向

本版合并第二轮三个并行分支（各自通过 Windows CI 与独立审查）。

- **解压 7z**（“解压归档”同一动作）：自写的有界 7z 读取与 LZMA、LZMA2、x86 BCJ、Copy 解码，校验头部与每个文件的 CRC，解码窗口最多 256 MB；加密、其他压缩方法、分卷、链接和特殊文件会拒绝。名称规则、10,000 项/2 GB/32 层上限、新文件夹独占发布和下载来源标记与 ZIP 相同。尚未用真实 7-Zip 软件制作的压缩包验收。
- **Doctor 列出 Store/MSIX 应用**：安装记录窗口中的 **Read Store and MSIX Packages…** 只读列出当前用户的包：名称、发布者、版本、架构、是否框架/资源/捆绑/开发包、安装日期；包系列名默认隐藏。上限 4,096 个包、约 10 秒；包管理器不可用时显示为状态，不报错。不包括其他用户或预配的包，不提供卸载。
- **去元数据时保留照片方向**：JPEG/PNG 去元数据新增“保留方向”（方向为 2–8 时默认勾选），用只含方向的最小 EXIF 替换原 EXIF，其余保留字节不变；原 EXIF 格式不规范、重复或有多个时只报告、不保留方向。

## 0.126 新增：三项并行完成的功能

本版合并三个并行会话各自完成、各自通过 Windows CI 和独立审查的分支。

- **应用内存：辅助进程归到所属应用**（可选，默认关闭）。用两次只读的进程快照取父进程编号，只有两次一致、父进程在同一快照中、子进程启动不早于父进程、且子进程程序位于父进程程序所在文件夹或其子文件夹时，才归入父进程所在的组；Windows 系统文件夹和磁盘根目录的父进程、循环和未知进程都保持单独。原来按完整路径分组的方式不变。
- **检查文档文字读取 EPUB 2/3 电子书**（Agent 的 extract_text 也支持）：按书的阅读顺序（spine）读取各章 XHTML 正文，规则与 HTML 读取相同。越界路径、大小写或反斜杠的同名条目、加密或带版权保护的书、DTD 实体和非 UTF-8/16 的 XML 会拒绝；不读取字体等其他资源。上限：文件 8 MiB、每个 XML 8 MiB、XML 合计 32 MiB、输出 2M UTF-16 字符。
- **WAV 变速新增“保持音调”**（默认开启，25–400%）：自写的 WSOLA 时间伸缩（40 ms 片段、75% 重叠、±10 ms 相似度搜索）。关闭时与原来音调随速度变化的 50–200% 输出逐字节相同。预算仍为 512 MiB、两小时。短于 40 ms 的声音不会均匀伸缩；真实人声和音乐的听感尚未验收。

## 0.125 新增：音频降噪支持 MP3、AAC 和 FLAC

“减少噪音”改名为 **Reduce Audio Noise…**，除 WAV 外也接受 MP3、AAC（ADTS）和 FLAC：先用“用 Windows 解码音频”的同一套 Windows 解码器把整个文件在内存中解码为 16 位 PCM（上限 128 MiB、两小时；解码器可能改变精度、起始静音或尾部填充），再进入原来的降噪窗口，结果另存为原文件旁边的新 WAV。窗口会注明文件经过解码。WAV 输入的处理和结果与以前完全相同。

## 0.124 新增：移动文件支持只读文件和硬链接

“移动文件”（含 Agent 工具的 plan_move）现在也接受只读文件和硬链接，与 0.123 的批量改名一致：同一 NTFS 卷内移动只是改名，只读文件移动后仍是只读，硬链接只移动所选的那个名称。所选路径中有同一文件的两个名称时，窗口和 Agent 计划都会明确说明，要求分开移动。跨卷移动、文件夹移动和云占位文件仍不支持。

## 0.123 新增：批量改名支持只读文件和硬链接

批量改名（含 Agent 工具的 plan_rename）现在接受只读文件和硬链接：改名只改所选的那个名称，只读文件改名后仍是只读，硬链接的其他名称不变，撤销照常按身份核对。仍会拒绝：没有 NTFS 文件标识的文件、同一批中同一文件的两个名称（Agent 计划时就逐行标出）以及被其他程序占用的文件。移动文件仍不接受只读文件和硬链接。

另外修正 Agent 工具压缩文件夹的指纹：NTFS 会延迟更新父目录中记录的文件夹时间，刚建好的文件夹可能被误判为“已改变”，现在只按名称计入文件夹（文件仍计入大小和修改时间）；并加入根文件夹本身的身份，换成另一个内容列表相同的文件夹会被拒绝。

## 0.122 新增：Agent 工具可压缩文件夹

Agent 工具（MCP，默认关闭）新增 `plan_zip_folder`：给一个文件夹路径，返回将要创建的 ZIP 名称、文件数、大小和跳过的项目，规则与“将文件夹压缩为 ZIP”相同。`apply_plan` 执行时重新读取文件夹，只要任何条目的名称、大小或修改时间、或跳过的项目与计划时不同就拒绝；写出的 ZIP 记入历史，`undo` 可移到回收站。Claude Desktop 扩展同步列出这个工具。

## 0.121 新增：复制文件夹到…

“移动文件”开关（默认关闭）下新增 **Copy Folder to…**：选择一个文件夹，再选择目标文件夹，整个文件夹树会复制为目标中的同名新文件夹（名称已占用时用“名称 2”）。确认窗口先列出来源、目标、数量、大小和跳过的项目。

- 文件用与“复制到文件夹”相同的方式复制：保留所有数据流（包括下载警告）、属性和修改时间，不覆盖任何内容；文件夹逐个独占新建，使用新时间和目标位置的权限。
- 跳过规则和上限与“将文件夹压缩为 ZIP”相同（链接、云端、系统文件、不支持的名称、超长路径、大小写重名；10,000 项、32 层、2 GB）。
- 目标在来源文件夹内部、复制后路径会超过 240 个字符、目标不是 NTFS 或空间不足时，复制前就会拒绝。中途出错或取消时，已完成的副本保留。

## 0.120 新增：将文件夹压缩为 ZIP

归档功能（Archives，默认关闭）新增 **Compress Folder to ZIP…**：选择一个文件夹，把文件夹本身和其中所有文件、子文件夹（包括空文件夹和隐藏文件）压缩成“文件夹名.zip”，保存在文件夹旁边；名称已占用时用下一个编号。每个文件保留修改时间。确认窗口先列出文件数、文件夹数、总大小和跳过的项目。

- 链接、联接点、仅在云端的文件、系统文件（如 desktop.ini）、Windows 不支持的名称（如 Mac 的 Icon 文件）、超过 240 个字符的路径以及只有大小写不同的重名项目会跳过并逐个列出，从不跟随或下载。某个文件被占用或无法读取时，提示会写明是哪个文件。
- 读取期间文件夹及其上级保持占用；每个文件都经已占用的文件夹重新打开并核对身份，读取过程中文件被改动则整个 ZIP 不保存。
- 上限 10,000 个项目、32 层文件夹、2 GB。不保留文件属性、权限和备用数据流。

## 0.119 新增：TGA 和 PSD 图片读写（跟进 Mac 1.14.x）

图片工具现在接受 **TGA** 和 **PSD**，转换菜单新增 **Convert to TGA** 和 **Convert to PSD**（Agent 工具同样可用）。读写都是 Swivel 自写的有界代码，不调用电脑上安装的图片编解码器：

- **TGA 读取**：调色板、真彩色（15/16/24/32 位）和灰度（含灰度+透明度），不压缩或 RLE 压缩，任意起点方向。TGA 2.0 扩展区说明透明度的意义；没有扩展区而透明度全部为 0 的旧文件按不透明读取。
- **TGA 写出**：不压缩；全不透明时 24 位，有透明部分时 32 位，并写明透明度。
- **PSD 读取**：8 位 RGB 和灰度，不压缩或 PackBits 压缩，读取 Photoshop 勾选“最大兼容”时保存的合并画面（不单独渲染图层、文字和效果，不应用内嵌颜色描述文件）。文件只有一个铺满画布的普通图层时直接用该图层的颜色；否则，Photoshop 写的文件（带它的版本信息）按混在白底上还原半透明颜色，其他程序（如 macOS）写的按原色读取。未勾选“最大兼容”保存、没有真实合并画面的文件会明确拒绝。16/32 位、CMYK、Lab、索引色、ZIP 压缩和大文档 PSB 会明确拒绝。
- **PSD 写出**：一张合并后的 8 位 RGB 画面（PackBits）；有透明部分时另带一个同样内容的普通图层，Photoshop 打开可见透明。

已知差异：macOS 的预览（ImageIO）读取带半透明边缘的 PSD 时颜色不准，它读自己写的 PSD 也一样；Photoshop 按图层打开不受影响。JPEG 2000 和 EXR 仍未支持（前者编码复杂，后者是 HDR，与 Windows 版只输出 8 位 SDR 的规则冲突）。

## 0.118 新增：Windows 医生“清理文件”（跟进 Mac 1.14.5）

Windows 医生的 **Clean Up Files** 区域（原 Uninstall Apps）新增 **Clean Up Files…**：点一下，按顺序在四个地方查找，结果放进一个分组列表：

- 已知浏览器和应用的缓存文件夹；
- 临时文件夹中 7 天未改动的项目；
- “下载”中 5 MB 及以上的安装包；
- “文档”、“桌面”和 source 文件夹里的项目构建文件夹。

每组默认折叠，组标题有一个可整组勾选的复选框，并显示项目数和大小；每行也有自己的复选框（选中行后按空格也能勾选）。与 Mac 相同，只有未在运行的应用的缓存会预先勾选，其他都要自己勾。一个按钮把所有勾选的项目移到回收站，确认框列出完整路径；每一项移动前都按找到它的那个工具的规则再检查一次。窗口打开期间可以撤销。

与 Mac 的差异：Mac 还列出很久没打开的应用、已删除应用的残留、重复与相似文件和超过 500 MB 的大文件。Windows 没有可靠的桌面程序上次打开时间，已卸载应用的残留需要卸载前的安装记录，所以这些仍在各自的工具里（窗口中会说明）。每个地方都按原工具的范围读取（四层、20,000 个条目、约 30 秒），列表可能不完整。

## 0.117 新增：晾衣绳上拼接图片（跟进 Mac 1.13–1.14.4）

在晾衣绳窗口里，把一张晾挂的图片拖到另一张的**下半部**，停留半秒（目标图片底边加粗、窗口底部出现两张缩略图的预览），然后松开：拖动的那张拼在目标下方，存成新的 PNG “上方图片名 stitched.png”，放在上方图片旁，重名时编号，不覆盖。新图片替换上方图片在晾衣绳上的位置，两张原图不改动，只是从晾衣绳上取下（重新晾挂即可再看到）。不想拖动时，可以右键一张图片，选 **Stitch Another Print Below** 再选另一张。

与 Mac 相同：整张拼接，宽的那张缩小到窄的宽度，不放大、不裁切、不变形，不猜测重叠部分；保留透明度；多帧、HDR 和高位深图片会被拒绝。

Windows 的差异：Mac 的晾衣绳是屏幕顶端的绳子，拖到目标下方的通道并带果冻般的融合动画；Windows 的晾衣绳是网格窗口，用“目标下半部 + 停留半秒”表示有意拼接，只有边框高亮和小预览，没有融合动画。结果最多 1600 万像素、每边 16384 像素（与 Windows 其他图片工具的上限相同，以便结果还能再处理；Mac 为 4000 万像素、32768 像素），两张大照片可能超出而被拒绝。

## 0.116 新增：转换为 ICO 图标（跟进 Mac 1.14.4）

图片的转换菜单里有 **Convert to ICO**（也可放进 Wheel／My Wheel、一次选多个，Agent 工具 `plan_action` 的 `convert.ico` 同有）。与 Mac 相同：按 16、32、48、64、128、256 像素保存，只保存不超过图片长边的尺寸（太小的图片至少放大成 16），每个尺寸都把整张图片按长边缩放、居中放在透明方块上，不拉伸也不裁切。新文件 “名称 converted.ico” 存在原文件旁，重名时编号，不覆盖。

Windows 的差异：Mac 交给 ImageIO（ICO 最多 6 个尺寸），Windows 是原创写出：128 及以下存为带透明度的 32 位位图（附 AND 掩码，旧版 Windows 也能读），256 存为 PNG（Windows Vista 起支持）。与其他输出一样为 8 位 SDR，不保存元数据和色彩配置。不提供 ICNS（Mac 图标格式）。

## 0.115 新增：字体格式转换（跟进 Mac 1.14.4）

TTF、OTF、WOFF、WOFF2 字体的工具里有 **Convert Font to WOFF／WOFF2**（不提供文件本身的格式），网页字体（WOFF、WOFF2）还有 **Unpack Web Font to TTF/OTF**：按轮廓类型还原为 TTF（TrueType）或 OTF（PostScript/CFF）。也可放进 Wheel／My Wheel、一次选多个，Agent 工具的 `plan_action` 也有。新文件存在原文件旁，同名换扩展名，重名时编号，不覆盖。

Windows 的差异：Mac 读取 WOFF2 交给系统的 CoreText；Windows 没有对应接口，Swivel 按 W3C WOFF2 规范自己还原 glyf/loca 与 hmtx 变换（大多数网页字体都用了这些变换），字形按参考解码器的方式紧凑写回。用 fontTools 对 242 个 macOS 自带字体做了对照：转成带变换的 WOFF2 后由 Swivel 还原、以及 Swivel 写的 WOFF/WOFF2 由 fontTools 读回，241 个逐字形、逐度量一致，另 1 个是 fontTools 自己读不了的位图字体。原字体里的数字签名（DSIG）原样保留，但文件重新排版后不再对应（Mac 相同）。

## 0.114 新增：数据文件互转（跟进 Mac 1.14.4）

JSON、JSON Lines（.jsonl／.ndjson）、属性列表（.plist，XML 或二进制）、CSV、TSV 文件的工具里有 **Convert Data to JSON／JSONL／PLIST／CSV／TSV／YAML**（不提供文件本身的格式），也可放进 Wheel／My Wheel，可一次选多个，Agent 工具的 `plan_action` 也有。新文件存在原文件旁，同名换扩展名，重名时编号，不覆盖。

与 Mac 相同的规则：值不猜测——CSV/TSV 单元格一律是文字；表格第一行是列名（空的叫 `column N`），每行变成一条记录，短行补空；记录转表格时列按首次出现顺序，嵌套值写成 JSON 文字；CSV 带 BOM 方便 Excel 打开中文；JSON 键排序、数字保留原文；YAML 字符串一律加引号；plist 的日期和二进制数据在 JSON/YAML 里写成 ISO 8601 和 Base64。目标格式装不下的值会停止并说明：plist 不能存 null 或超出 64 位整数/双精度的数，JSON/CSV/TSV 不能存 NaN/无穷大，TSV 单元格不能有制表符或换行。

Windows 的差异：只读 UTF-8 或带 BOM 的 UTF-16（旧编码拒绝）；同一对象里重复的键直接拒绝而不是保留其中一个；为控制内存，JSON 最多 400 万个值、表格最多 500 万个单元格、输出估算最多 128 MB（Mac 为 1000 万单元格、256 MB）。输入最大 32 MB、100 万行、16384 列、嵌套 128 层；二进制 plist 中被多处引用的对象按展开后的总量计算。

## 0.112 新增：剪辑视频

视频（MP4、MOV、M4V、WMV）的工具里新增 **Trim Video…**，也可放进 Wheel／My Wheel。窗口里输入开始时间和结束时间（秒、分:秒或时:分:秒，最多三位小数，例如 `1:05.5`），停止输入约 0.25 秒后，两侧各显示 Windows 在该处的画面：大致是开始处一帧和保留部分的最后一帧（可能相差一帧）。可取消 **Keep the sound** 去掉声音；只去声音、不改时间也可以。保留不到 0.1 秒、开始不早于结束、超出视频，或者保留全部且有声音时，下方说明原因，Trim 按钮不可用。

D04 仍为部分实现：画面裁切／旋转、颜色、变速、配乐和同步预览播放仍待做。未验证：真实电脑上的硬件编码器、长视频与 4K 的耗时、窗口在真实 Windows 上的操作手感。

## 0.111 新增：手机竖拍等带旋转标记的视频

手机拍的视频常以横向画面存储，再在 MP4 轨道头里写一个旋转标记（90°、180° 或 270°）。先在 GitHub 的 Windows 运行器上做了探测：Windows 自带的媒体编辑接口读到这个标记后会自己把画面转正，报告转正后的尺寸（例如 3840×2160 存储、转 90° 的报告为 2160×3840）。因此 Agent 工具的 `plan_compress` 和视频工具 **Burn In Subtitles…** 不需要新算法，按转正后的尺寸编码，输出就是正的、不再带旋转标记。原先“旋转视频暂不支持”的说明已改。

烧录字幕的尺寸上限改为横竖均可：长边最多 3840、短边最多 2160，所以 4K 竖拍视频（转正后 2160×3840）不再被拒绝；字幕按转正后的画面放在底部。只有 Windows 报告了旋转却可能没有应用时才拒绝，并说明原因。

新增原生检查：用 Windows 生成一个四角标色的测试视频，按手机写法改写轨道头为 90°/180°/270°，确认压缩后尺寸、长度、目标大小、四角颜色都对且没有残留旋转；90° 视频烧录字幕后字幕只在字幕时间内出现在底部；一个 4K 视频转 90° 后按 2160×3840 烧录成功。未验证：真实手机拍摄的 MOV/MP4（只测了改写轨道头的 MP4）、硬件编码器对竖向 4K 的支持（CI 用的是软件编码）、180°/270° 视频的字幕烧录。

## 0.109 新增：Agent 工具转换文档文字

## 0.108 新增：Agent 工具按大小压缩（可撤销）

Agent 工具（MCP）新增 **`plan_compress`**：把 1–100 个图片或视频各压到不超过 `target_bytes` 字节（1,000 到 1,000,000,000,000 的整数），新文件以 `名称 compressed.jpg` / `名称 compressed.mp4` 放在原文件旁，名字被占用时依次加编号，绝不覆盖，原文件不动。图片（PNG、JPEG、BMP、TIFF、静态 GIF，最多 1600 万像素、每边 16384）一律输出 JPEG：透明部分铺白底、不带元数据，先找能放下的最高质量（1–100），连最低质量都放不下时长边每次缩短 15%，最小到 320 像素（原图更小就不缩）；仍放不下就拒绝并说出能做到的最小字节数。视频（MP4、MOV、M4V、WMV，最长 2 小时、每边最多 8192 像素）用 Windows 自带的媒体编辑接口重新编码成 H.264/AAC MP4：按长度算总码率并留 5% 和 4 KB 给容器，有声音时 AAC 用 96 或 128 kbit/s（Windows 的 AAC 编码器只接受 96/128/160/192），视频码率不超过原片；画面大小按目标允许的码率定，码率低时长边降到 640/854/1280/1920（原片码率本来就低时不缩），边长取偶数，帧率保持（最多 60）；先在临时文件夹编码，超出目标就按超出比例再试一次（已是最低码率和尺寸则直接停止），仍超出则不保存；被强行结束时留下的临时文件夹满一天后由下次压缩清掉。计划时就会拒绝对视频长度来说太小的目标并给出最小值；旋转存储的视频（手机常见）暂不支持。参数 `format` 可省略、`same`（只在所有文件都已是 JPEG 图片或 MP4 视频时）或 `jpg`（也认 `jpeg`）；`heic`、`png` 会被拒绝并说明 Windows 版只输出 JPEG。

`apply_plan` 照旧先核对每个输入没被换掉或改过，逐个生成，每个文件被租住后还会再核对一次（压前一个视频要几分钟，期间改过的后一个文件会被拒绝），一个失败就停下并保留、记录已完成的文件；历史里是普通的新建文件条目（动作 `compress`），旧版也能读，`undo` 把未改动的结果移入回收站。`inspect_files` 对图片和视频列出 `plan_compress`。设置页说明已改写（四语）。G02 仍为部分实现（MCPB 打包、真实 agent 主机仍待验证），固定 52 项仍 27／23／0／2。原生测试已在 GitHub 的 Windows 运行器上通过（生成的 6 秒测试视频与图片）；真实手机视频、长视频和真实 agent 主机仍未验证。

## 0.107 新增：Agent 工具移动文件（可撤销）

Agent 工具（MCP）新增 **`plan_move`**：把 1–100 个文件移到同一 NTFS 驱动器上一个已有的文件夹，保留文件名。参数只有 `paths` 和 `destination`（目标文件夹的完整路径，末尾的 `\` 可有可无），拼错的参数名会被拒绝；路径必须和磁盘上的文件名写法完全一致（大小写相同、不是 8.3 短名），因为移过去的文件就用这个名字。计划时列出每个旧路径和新路径，逐行标出问题：已经在这个文件夹里（目标文件夹用 8.3 短名或别的写法也认得出）、目标里已有同名文件或文件夹、两个所选文件同名、Windows 不能用的路径、Swivel 移不了的文件（在另一个驱动器或文件系统、只读、硬链接）。与 Mac 版不同，同名时不会改成 `名称 2`，也绝不覆盖；只移文件，不移文件夹。全部没问题才给 `plan_id`，在 `apply_plan` 之前不改任何东西。

应用时用“移动文件”的同一套租约和事务：在租约下再次核对目标文件夹仍是计划时那一个（删掉后在原路径新建的不算）、每个文件没被换掉、改过或改了名字写法，目标名字仍空闲；一步失败就把已移的全部移回，移不回的如实列出现在位置并记入历史。历史里移动记录仍带空的 `outputs` 列表，旧版仍能读这份历史（只是看不到移动项）。`undo` 像新建文件的撤销一样**逐个**处理：文件没改动、原位置的名字空闲就移回原文件夹；改动过、不见了、原文件夹已不在或原名已被占用（原位置留着它的硬链接也算占用）的文件留在原处并说明原因，其余照样移回；已经回到原位置的文件会被认出并记为已撤销；`dry_run` 只报告，也会打开同样的租约检查，实际会被拒绝的文件（例如之后改成只读）如实说明。存档位已清除的文件也能移动（改名时 NTFS 可能设置存档位，“移动文件”现在只忽略这一位）。设置页说明已改写（四语）。G02 仍为部分实现（按目标大小压缩、MCPB 打包仍待做），固定 52 项仍 27／23／0／2。真实 agent 主机与 Windows 上的真实移动未验证。

## 0.106 新增：Agent 工具批量改名（可撤销）

Agent 工具（MCP）新增 **`plan_rename`**，参数与 Mac 版相同：`base_name` 整体换名、`find`／`replace_with`（区分大小写）、`prefix`、`suffix`（加在扩展名前）、`number` 按路径顺序加 `-001` 编号（`start`、`digits` 可调）。只改文件名、保留扩展名，文件留在原文件夹，一次 1–100 个文件，每段文字最多 120 个字符。加上去的文字（base_name、replace_with、prefix、suffix）不能含 `\`、`/`，也不能含不可见、看起来像空格或改变文字方向的字符；路径必须和磁盘上的文件名写法完全一致（大小写相同、不是 8.3 短名），因为新名字和撤销后的名字都由它算出；`start`、`digits` 只在 `number: true` 时可用，拼错的参数名会被拒绝。计划时列出每个旧名和新名，逐行标出问题：Windows 不能用的名字、扩展名前什么都不剩、两个文件撞名（不区分大小写）、名字已被其他文件或文件夹占用、Swivel 改不了的文件（不在 NTFS、只读、硬链接）；名字不变的文件不检查、也不参与应用。全部没问题才给 `plan_id`，在 `apply_plan` 之前不改任何东西。互换、连锁改名和只改大小写都可以（先挪到临时名再改，与“批量改名”同一套代码）。

应用时再次核对每个文件没被换掉、改过或改了名字写法，一步失败就把已改的全部改回；改不回的会如实列出它现在的位置并记入历史。历史里改名记录仍带空的 `outputs` 列表，0.86–0.105 的旧版仍能读这份历史（只是看不到改名项）。`undo` 把同一次改名的文件**一起**改回原名：任一文件被改动、不见了或原名已被占用，就一个都不改，并逐个说明原因；已经回到原名的文件（例如上次撤销后历史没存上）会被认出并记为已撤销；`dry_run` 只报告。G02 仍为部分实现（移动、按目标大小压缩、MCPB 打包仍待做），固定 52 项仍 27／23／0／2。真实 agent 主机与 Windows 上的真实改名未验证。

## 0.105 新增：Agent 工具读码与取文字

Agent 工具（MCP）新增两个只读工具，不写文件，Swivel 不联网：

- **`extract_text`**：图片用 Windows 自带 OCR 识别文字。需要 MSIX 安装包和已安装的识别语言；ZIP 版或没有语言时逐个文件说明原因，不会去解码图片。可传 `language`（如 `zh-Hans-CN`，不区分大小写），必须是已安装的语言，否则整次拒绝并列出已安装的语言；不传则按用户的语言设置。纯文本、DOCX、ODT、RTF、静态 HTML 文档读正文文字，限制与“检查文档文字”相同，`language` 对文档不起作用。每个文件超过 200,000 个 UTF-16 单位、或一次回复累计超过 400,000 时拒绝该文件（后面较小的文件照常返回），绝不截断；agent 主机自己也可能缩短很长的回复，所以每次少传几个文件。
- **`read_codes`**：每张图读一个清晰的平面二维码（方形、正放或按 90° 旋转、完整四格白边、像素清晰，整数倍放大可以），返回原文、版本和纠错级别；照片、损坏或裁切的码、平滑缩放过的图和条形码读不出，会列出原因。读出的文字不代表来源可信、链接安全。

## 文件及平台边界

图片上限128 MiB、1600万像素、单边16384像素；像素规范化为8-bit SDR sRGB，常规编码器设置96 DPI（GIF不存DPI/ICC），应用 EXIF 方向并去除内嵌元数据。静态GIF只限完整画布/方形像素及明示扩展子集；拒绝多帧/APNG/动画GIF、HEIC/AVIF/WebP、HDR、高位深、CMYK。画布和拼图另有4000像素边长上限。所有格式与效果仍需 Windows 编解码和视觉验收。

输入限240字符以内的本地普通文件路径，不接受文件夹、UNC/映射网络盘、设备路径、备用数据流、链接或 junction 父目录、云占位文件。带 reparse point 的同步目录也可能被保守拒绝。原件在本地处理时持有只读句柄；改名使用专用 DELETE 句柄及身份检查；外部应用接收文件路径后自行负责读写。

临时输出原子创建，通过同一句柄不覆盖发布。取消等待当前系统编码/系统调用返回，清理尚未发布的输出，已完成项保留并显示；强制终止/断电可能留下 `.swivel-*.tmp`。没有启动扫描/自动删除。Optional 功能关闭时会取消所属操作，包括加载阶段。

本版没有自动启动、截图接管、剪贴板读取或 MCP。0.53助手仅在独立开启并完整预览后明确发送，基本Doctor脱敏解释及单次明确选择的自定义动作标签已接入；音频已有限定系统解码，PDF/OCR已有需MSIX身份的条件路径（普通ZIP不可用）。其他媒体/视频、完整PDF保真、更完整Doctor诊断、AI模型、拍照／透视模糊或结构损坏二维码读取、安全复制／跨卷移动／目录树／解压等仍见 PORTING；0.77仅补同卷NTFS普通文件移动及会话撤销。“尚未实现”不等于平台不兼容。

```powershell
./Windows/build.ps1 -Runtime win-arm64
```

脚本先运行核心及当前宿主 Windows 原生检查，再生成对应架构自包含包；x64上交叉构建ARM64不等于运行ARM64。`-SkipTests`仅跳过检查。

Mac/Linux交叉构建：

```sh
bash Windows/build.sh win-x64
bash Windows/build.sh win-arm64
```

可设置 `SWIVEL_DOTNET=/absolute/path/to/dotnet`。各版产物位于 `build/windows/<版本>/<架构>`，本轮最终版本为 `0.79.0`；版本包与输出目录已存在时，构建脚本会拒绝覆盖，重建需新版本或明确备份。脚本运行核心规则并编译原生测试；**无法在 Mac 运行 Windows 程序**。不要把交叉编译或agent代码审查当作Windows运行、拖放、焦点、DPI、文件系统、ARM64和视觉验收。未推送/触发云CI/安装本包。

## 迁移文件来源

Mac 二维码库原文件是 `~/Library/Application Support/Swivel/QRCodes/library-v1.json`；复制该文件到 Windows 后使用 **Import Mac QR Library…**。Windows 只读取明确选中的本地副本，不扫描其他应用、修改源库或打开链接。

Mac 图片预设当前保存在 `imagePresets.v1` 的 JSON Data 中，Mac 应用本身尚无独立的导出按钮。Windows接受已经取得的原始 `ImagePreset` JSON 数组；不能直接选择整个偏好设置plist或Windows设置文件。此次没有更改Mac导出界面或自动读取Mac设置。Windows原生备份可直接使用 **Export Image Presets…** 生成，导入入口也支持这种备份。

不兼容条目仍完整显示，确认只添加兼容项。备份只含配方或已保存二维码内容，不含API密钥；二维码内容是明文，应检查保存位置。导入不会改变任何工具开关，也不会替换已有配方或库文件。
